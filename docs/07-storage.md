# 07. Хранилище знаний

На старте — локальная папка (путь задаётся в настройках приложения, по умолчанию `Documents/knowledge-hub`), внутри которой можно сделать `git init`: история и откат появятся бесплатно, а позже папку можно превратить в репозиторий с MR (другая реализация `KnowledgeStore`). MCP-режим читает ту же папку.

## Раскладка

```
knowledge/
  <service-id>/
    service.yaml                 # schemaVersion, имя, репозиторий, ветка, стек, последний проанализированный коммит
    database.yaml                # схема БД: источники данных (без учётных данных), таблицы, колонки, ключи, сущности
    config.yaml                  # свойства: значения по профилям (секреты замаскированы), кто их читает
    database.md, config.md       # СГЕНЕРИРОВАНО: справочники БД и конфигурации
    features/
      <feature-id>/
        feature.yaml             # модель: триггеры, шаги, стоки, claims, статусы, evidence
        README.md                # СГЕНЕРИРОВАНО: описание фичи
        flow.mmd                 # СГЕНЕРИРОВАНО: диаграмма потока
    diagrams/
      context.mmd                # СГЕНЕРИРОВАНО: L1
      components.mmd             # СГЕНЕРИРОВАНО: L2
      er.mmd                     # СГЕНЕРИРОВАНО: ER-диаграмма
    .state/                      # не коммитится: hub.db (запуски, чекпойнты, очередь ревью, журнал), index.db (FTS5), history/
```

## Правила

- **Правится только модель** (через ревью). Сгенерированные файлы содержат заголовок «generated, do not edit» и пересоздаются.
- Сгенерированные файлы коммитятся ради читаемости и диффов в git.
- `.state/` содержит рабочие данные (запуски, очередь ревью, индекс) и в git не попадает.
- Формат `feature.yaml` версионируется `schemaVersion`; старые версии читаются миграцией.
- Идентификаторы фич — slug, неизменные после подтверждения (переименование — отдельная операция с алиасом).

## Хранение запусков и ревью

Метаданные запусков, очереди ревью и журнал действий ревьюеров — в SQLite внутри `.state/` (Rust, `state.rs`, за интерфейсом, чтобы заменить). Итог подтверждения попадает в `feature.yaml` (статусы claims), остальное — журнал.

## Конфликты

Если анализ предлагает изменение claim со статусом `EDITED`/`HUMAN`, создаётся пункт ревью «конфликт», а человеческая правка не перезаписывается молча.
