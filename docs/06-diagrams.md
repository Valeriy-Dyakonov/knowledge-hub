# 06. Диаграммы

Диаграммы **генерируются из модели** рендерером, а не рисуются LLM. Так они единообразны, согласованы с текстом и ревьюятся через claims.

## Уровни

| Уровень | Что показывает | Аудитория |
|---|---|---|
| L1. Контекст | сервис, кто к нему обращается, с какими системами работает и ради каких фич | все, включая нетехнических |
| L2. Карта фич | фичи по областям, системы каждой фичи, цепочки фича → топик → фича | аналитики, разработчики |
| Компоненты | техническая схема: классы по слоям (точки входа → логика → доступ к данным) | разработчики |
| L3. Поток фичи | sequence: триггер -> шаги -> сток | разработчики и ревьюеры |
| ER | таблицы, колонки, PK/FK (Mermaid `erDiagram`); на экране «База данных» — вся схема (до 25 таблиц) или таблица с соседями по внешним ключам | разработчики, аналитики |

## Правила читаемости

- Не более 10–12 узлов на диаграмму; больше — делим по подфичам или группируем.
- Подписи — `businessName`; технические названия показываются в подсказке/вторым уровнем.
- Единые формы и цвета по виду узла: триггер, компонент, БД, очередь, внешний сервис.
- Направление слева направо; триггеры слева, стоки справа.
- Каждый узел и ребро связаны с claim (для перехода к evidence и ревью).

## Формат

Начинаем с Mermaid (текстовый, диффится, рендерится во многих средах). Рендерер — интерфейс, так что D2/C4/другие форматы добавляются реализацией. В приложении диаграммы рисуются библиотекой `mermaid` из того же текста; клик по узлу открывает его claims и evidence.

## Реализация

`src/lib/render/mermaid.ts` — одни и те же функции для файлов и для приложения:
- **L1** `contextDiagram`: слева «Кто обращается» (клиенты API с числом фич по областям, топики, которые сервис слушает, задачи по расписанию с названиями), справа «С чем работает» (база данных со списком таблиц, публикуемые топики, внешние API). На стрелках — что сервис делает и для каких фич («пишет: Создание возврата, Одобрение…»).
- **L2** `featureMapDiagram`: фичи (бизнес-название + тип входа) в рамках областей и системы, с которыми работает каждая; топик, который одна фича публикует, а другая получает, связывает их в цепочку. Больше 12 фич — сворачиваются в области; много систем — группируются по виду.
- **Компоненты** `componentsDiagram`: классы по слоям (точки входа → логика → доступ к данным и API → хранилища и внешние системы); больше 12 узлов — сворачиваются по видам.
- **L3** `flowDiagram`: sequence-диаграмма фичи по шагам `flowSteps` (`src/lib/model/flow.ts`): вызов репозитория или клиента и его запись/чтение показаны одним шагом «сервис пишет в таблицу (через RefundRepository)»; повторные вызовы одного метода — один шаг. Больше 12 участников — компоненты одного вида делят линию. Выведенные связи — пунктир с пометкой.

Формы и цвета: кто обращается — овал, фича — скруглённый прямоугольник, компонент — прямоугольник, БД — цилиндр, очередь/топик — параллелограмм, внешний сервис — шестиугольник; легенда — под схемой в приложении. Связи с отклонёнными claims не показываются; перед рёбрами — `%% claim <id>`. Фигурные скобки путей (`{id}`) в подписях рёбер экранируются.

**Без «ещё N».** Большая группа (больше 8 элементов) не обрезается, а сворачивается в один пунктирный узел «Таблицы: 23 — нажмите, чтобы раскрыть»; в приложении клик раскрывает её целиком. В записанных файлах все группы раскрыты. L1 построен из рамок («Клиенты API» по областям, «Слушает топики», «Задачи и события», «База данных», «Публикует в топики», «Внешние сервисы»), стрелки идут от рамки к рамке.

**Раскрытая группа** больше 6 элементов раскладывается колонками: по общему префиксу имён (`refund_*`, `payment_*`, топики `refunds.*`), если он делит большинство элементов на группы, иначе ровной сеткой (невидимые колонки).

**Масштаб.** Каждая схема в приложении — в окне с масштабом и сдвигом: Ctrl + колесо — масштаб вокруг курсора, колесо или перетаскивание — сдвиг, кнопки «−», «100 %», «+», «Вписать» (или двойной щелчок), «Во весь экран».

**Интерактивность в приложении.** Узлы кликабельны (`DiagramSpec.nodes` связывает id узла Mermaid с ключом): таблица, топик, область или компонент открывают под схемой список фич, которые с ними работают, и что делают; фича открывается на экране «Фичи». Карта фич (L2) в приложении по умолчанию — таблица «фичи × системы» (строки — фичи по областям, сворачиваются; столбцы — таблицы, топики, внешние API; в ячейке — З/Ч/П/Пол/В). Компоненты — с погружением: «Все компоненты › Сервисы › RefundService»: вид → список компонентов с поиском → окружение компонента (кто вызывает, кого вызывает он, куда пишет).

Рядом со схемами в приложении — тот же смысл словами: таблица «Система — как — ради каких фич» (`src/lib/render/overview.ts`) и «Что делает сервис» по областям с описаниями фич (после Describe и ревью).

Файлы: `diagrams/context.mmd`, `diagrams/features.mmd`, `diagrams/components.mmd`, `features/<id>/flow.mmd`; README сервиса и фич встраивают те же диаграммы. Тесты проверяют синтаксис каждой диаграммы через `mermaid.parse` и ограничение на число узлов.

## Ревью диаграмм

Ревьюер видит превью и список claims, из которых оно собрано. Правка идёт в модели; диаграмма перестраивается. Ручной правки изображений нет.
