# Knowledge Hub

Сервис, который анализирует репозиторий (первый целевой стек: Kotlin + Spring Boot), раскладывает его на **фичи**, прослеживает каждый процесс от триггера до записи в БД или вызова внешнего сервиса и сохраняет результат как **проверенную человеком базу знаний**. Знания отдаются любому harness/агенту через **MCP**.

> Статус: **проектирование (M0)**. Кода ещё нет. Цель этапа — проверить на реальном сервисе, насколько подход применим (см. `docs/09-roadmap.md`, раздел «Критерии применимости»).

## Идея в четырёх пунктах

1. **Источник правды — структурная модель**, а не markdown. Каждое утверждение (claim) несёт evidence: `файл:строки@коммит`.
2. **Сначала детерминированный анализ кода, потом LLM.** Статика находит точки входа и стоки; LLM только называет, группирует и объясняет. Если LLM недоступна, остаются проверяемые факты.
3. **Markdown и диаграммы генерируются из модели.** Они всегда согласованы и выглядят единообразно.
4. **Ревью строгое, но с малым объёмом.** Нельзя «прожать всё». Человек подтверждает, правит или отклоняет конкретные утверждения с видимым evidence; в пачки подмешиваются контрольные пункты.

## Что намеренно НЕ делаем сейчас

- Никаких триггеров из CI/GitLab, вебхуков и автообновления по мержам. Запуск анализа ручной (CLI/UI).
- Никакой записи в анализируемые репозитории: хаб только читает.
- Векторный поиск на старте необязателен; базовый поиск — SQLite FTS.

## Как продолжать

Открыть папку в IDE, прочитать `AGENTS.md`, затем `docs/09-roadmap.md`. Следующий шаг — **M1: скелет Gradle-проекта** (модули, доменная модель, порты, пустой `kb-app`).

## Язык

`AGENTS.md`, код, комментарии и коммиты — на английском (как в worklog-tracker). Документы в `docs/` — на русском. Интерфейс ревью и бизнес-названия в знаниях — локализуются (ru/en).
