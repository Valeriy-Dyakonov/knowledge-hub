# Knowledge Hub

Десктоп-приложение (Tauri 2 + React/TypeScript, бэкенд на Rust), которое анализирует репозиторий сервиса, раскладывает его на **фичи**, прослеживает каждый процесс от триггера до записи в БД или вызова внешнего сервиса и сохраняет результат как **проверенную человеком базу знаний**. Всё в одном окне: выбрал репозиторий → запустил анализ → смотришь фичи, потоки, диаграммы → ревьюишь. Знания отдаются любому harness/агенту через **MCP** (тот же исполняемый файл в режиме `mcp`).

Первый целевой стек **анализируемых** репозиториев — Kotlin + Spring Boot. Другие языки добавляются экстракторами.

> Статус: **M1 — скелет приложения.** План — `docs/09-roadmap.md`.

## Идея в четырёх пунктах

1. **Источник правды — структурная модель**, а не markdown. Каждое утверждение (claim) несёт evidence: `файл:строки@коммит`.
2. **Сначала детерминированный анализ кода, потом LLM.** Статика находит точки входа и стоки; LLM только называет, группирует и объясняет. Если LLM недоступна, остаются проверяемые факты.
3. **Markdown и диаграммы генерируются из модели.** Они всегда согласованы и выглядят единообразно.
4. **Ревью строгое, но с малым объёмом.** Нельзя «прожать всё». Человек подтверждает, правит или отклоняет конкретные утверждения с видимым evidence; в пачки подмешиваются контрольные пункты.

## Что намеренно НЕ делаем сейчас

- Никаких триггеров из CI/GitLab, вебхуков и автообновления по мержам. Анализ запускается вручную из приложения.
- Никакой записи в анализируемые репозитории: хаб только читает.
- Векторный поиск на старте необязателен; базовый поиск — SQLite FTS5.

## Структура репозитория

```
AGENTS.md              правила для агентов и контрибьюторов (читать первым)
CLAUDE.md              ссылка на AGENTS.md
src/                   фронтенд: UI (React) и логика пайплайна (lib/, TypeScript)
src-tauri/             бэкенд: Rust (чтение репозитория, экстракторы, хранилище, индекс, LLM, MCP)
docs/                  проектная документация (на русском)
  00-vision.md         зачем, принципы, границы
  01-architecture.md   слои, порты и адаптеры, потоки данных
  02-domain-model.md   сущности, claim, evidence, статусы
  03-pipeline.md       стадии анализа, политика ошибок, экстрактор Kotlin/Spring
  04-review.md         строгое ревью и защита от «да-да-да»
  05-extension-points.md  интерфейсы расширения и чеклисты
  06-diagrams.md       уровни диаграмм и правила читаемости
  07-storage.md        раскладка базы знаний на диске
  08-mcp.md            инструменты MCP и формат ответа
  09-roadmap.md        этапы, критерии применимости, открытые вопросы
  10-worklog-tracker-patterns.md  что переносим из worklog-tracker
```

## Язык

`AGENTS.md`, код, комментарии и коммиты — на английском (как в worklog-tracker). Документы в `docs/` — на русском. Интерфейс и бизнес-названия в знаниях — локализуются (ru/en).
